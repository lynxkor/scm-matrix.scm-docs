## 1. 产品定位与目标

### 1.1 定位

OTWB 是面向物流与供应链运营企业（3PL、品牌方自营运配一体）的**一体化供应链执行平台**，名称含义：

| 字母 | 含义 | 承载方式 |
| --- | --- | --- |
| O | Order 订单 | OMS 自建服务：全渠道接单与订单编排 |
| T | Transportation 运输 | TMS 自建服务：运输计划与执行 |
| W | Warehouse 仓储 | **不自建**，通过集成层对接外部仓储系统（见 2.4） |
| B | Billing 结算 | BMS 自建服务：计费引擎与应收应付结算 |

配套建设 **MDM 基础资料服务**作为全局主数据中心，四个能力域共用一套主数据。

### 1.2 建设目标

1. **一个订单入口**：全渠道（网上门店、EDI、OpenAPI、手工、Excel）接单，统一编排仓储与运输作业；
2. **一套主数据**：贸易伙伴、物料、地址等主数据一处维护、全服务共用，消除编码不一致；
3. **仓运联动**：OMS 出库订单同时驱动外部仓储作业与 TMS 运输执行，状态全程可视；
4. **计费闭环**：业务单据状态变化自动驱动计费，凭证→对账单→收付款→发票全流程数字化；
5. **平台化**：多租户与域隔离、OpenAPI、消息、系统日志、自定义配置。

### 1.3 用户角色

| 角色 | 主要使用服务 | 核心诉求 |
| --- | --- | --- |
| 主数据管理员 | MDM | 贸易伙伴/物料/地址等档案维护与授权 |
| 客服/订单员 | OMS | 接单、改单、订单跟踪 |
| 调度/车队长 | TMS | 配载、指派、在途跟踪、异常处理 |
| 结算员/财务 | BMS | 凭证审核、对账、开票、收付款 |
| 客户（外部） | OMS 客户门户 | 自助下单、订单跟踪、对账单查询 |
| 仓库作业方（外部） | 外部 WMS | 接收出入库指令、回传作业结果与库存 |
| 系统管理员 | 平台 | 租户、用户、权限、系统设置、集成配置 |

## 2. 服务拆分

### 2.1 拆分原则

1. **按业务域拆分**：订单、运输、结算是三个独立演进的业务域，主数据单独成域；
2. **单一数据所有权**：每类业务数据只有一个属主服务，其他服务通过接口/事件消费，禁止跨服务直写；
3. **仓储能力集成而非自建**：本期不自建 WMS，仓储作业由外部系统承担，平台只保留指令下发与结果回传的集成边界；
4. **松耦合事件驱动**：跨服务协作优先采用事件订阅（如"发货订单审核"事件触发 BMS 计费），接口调用为辅；
5. **可独立交付**：每个服务可独立规划、开发、上线，按路线图分阶段交付。

### 2.2 服务总览

| 服务 | 服务码 | 定位 | 核心能力 | 关键单据 | 数据所有权（属主） |
| --- | --- | --- | --- | --- | --- |
| 基础资料 MDM | MD | 全局主数据中心 | 贸易伙伴、物料、地址、运输资源等主数据管理、域隔离、分仓同步、授权 | 各类主数据档案 | 全部主数据 |
| 订单管理 OMS | OM | 订单编排与库存可视 | 全渠道接单、订单审核发布、出入库指令编排、订单执行跟踪、全局库存可视化、客户门户下单 | 采购订单、销售订单、入库订单、出库订单 | 订单（中心与执行单据）、订单渠道信息 |
| 运输管理 TMS | TM | 运输计划与执行 | 发货订单、配载、运单、在途跟踪、节点到货、签收、回单 POD、货差、发货控制台 | 发货订单、分段、运单、回单 | 运输单据、运输资源占用记录 |
| 结算管理 BMS | BM | 计费引擎与结算 | 费率合同与计费模式、应收/应付凭证、合并发票、对账单、实收实付、发票、KPI 扣款 | 费率合同、凭证、对账单、实收/实付、发票 | 全部费用与结算单据 |

### 2.3 各服务职责详述

#### 2.3.1 基础资料 MDM

**职责清单**：

- 贸易伙伴主数据：货主、客户（含结算客户、关联租户）、供应商、承运商及其规则设置（收款计划、付款计划、凭证审核要求等）；
- 商品主数据：物料、包装、计量单位、批次模板、装箱组、组装件；
- 地域主数据：地址、省/市/区县、地区、电子围栏；
- 运输主数据：运输方式、服务级别、路线；
- 资源主数据：设备、挂车、司机、GPS 设备、车队（维修/年检/保险/保养/违章/费用）；
- 财务主数据：银行、汇率、税种；
- 通用机制：PUBLIC/用户域隔离、WMS 分仓数据分发、主数据授权、启用/停用/删除生命周期、导入导出、UDF 自定义字段、数据字典。

**上下游**：

- 向 OMS/TMS/BMS 提供主数据查询与变更订阅；
- 向外部 WMS 分发主数据（货主、客户、供应商、物料等分仓同步）。

**PRD 存放**：`01-基础资料MDM\`，编号 PRD-MD-xxx。

#### 2.3.2 订单管理 OMS

**职责清单**：

- 网上下单（客户门户）：客户身份用户自助下单，受物料订货限制约束；
- 订单中心：采购订单、销售订单、增值单（来源：手工、Excel、EDI、OpenAPI、网上门店）；
- 订单执行：入库订单、出库订单（拆单/合并、审核、提交、发布）；
- 库存可视化：全局库存查询、库存转移、货权转移；
- 订单编排：按作业类型（预约/仓储/运输/仓储运输）将订单分发至外部 WMS 与 TMS；
- 物料订货限制：定义物料与仓库、客户的可订货关系。

**上下游**：

- 消费 MDM 主数据；
- 出库订单推送 TMS 生成发货订单，入库/出库订单经集成层推送外部 WMS；
- 发布/审核等关键状态事件通知 BMS（触发计费）。

**PRD 存放**：`02-订单管理OMS\`，编号 PRD-OM-xxx。

#### 2.3.3 运输管理 TMS

**职责清单**：

- 订单与发货订单管理（手工、导入、OMS 推单、EDI/API 接入；送货预约、费用预估、比价）；
- 配载计划：手工配载、分段、批量分段、地图配载、路线配载、自动配载、波次计划、承运商指派；
- 运单执行：批准→委托→接受→确认→提货→在途→节点到货→签收→结案全状态流转与逆向操作；
- 回单与差异：POD 回单、货差管理、拒收/破损/丢失处理；
- 在途服务：货运轨迹、GPS/温控设备集成、快递轨迹集成、异常预警；
- 发货控制台与订单指派。

**上下游**：

- 消费 MDM 主数据（客户、承运商、地址、运输方式、设备司机）；
- 运单节点状态事件（提货/到货/签收）驱动 BMS 应收应付凭证生成与刷新；
- 可与关联租户（外部 TMS 租户）双向委托协同。

**PRD 存放**：`03-运输管理TMS\`，编号 PRD-TM-xxx。

#### 2.3.4 结算管理 BMS

**职责清单**：

- 计费引擎：费率合同（客户应收/承运商应付）、费率明细与分级、附加费、计费模式（标准/按立方/按趟次/包月）、暂估天数；
- 凭证管理：应收凭证、应付凭证的生成、审核/反审核、费用调整、刷新运费、合并发票（父/子发票、比例分摊）、结算日期；
- 对账管理：应收/应付对账单（手工/批量创建、系数调整、盲对模式）、开票方与发票抬头、收款计划分期；
- 收付款：实收/实付记录、部分收款/付款、撤销；
- KPI 考核扣款与承运商对账参考日。

**上下游**：

- 消费 OMS/TMS/外部 WMS 的业务事件与作业量数据计费；
- 消费 MDM 财务与贸易伙伴主数据（结算方式、税率、收款计划、付款计划）；
- 输出对账单/实收实付/发票数据至 ERP 总账。

**PRD 存放**：`04-结算管理BMS\`，编号 PRD-BM-xxx。

### 2.4 外部服务边界

| 外部服务 | 集成方式 | 边界约定 |
| --- | --- | --- |
| 外部 WMS（仓储） | 集成层：OMS 出/入库指令下发；WMS 回传作业状态、作业量、库存快照 | 平台不自建仓内作业功能（波次/拣选/复核/上架等）；仓储主数据由 MDM 分仓同步下发；仓储费按回传作业量由 BMS 计费；仓库/货位主数据随分仓同步维护 |
| ERP/财务 | OpenAPI + 财务接口 | 主数据（客户/供应商/物料）可双向同步；BMS 结算单据推送总账 |
| EDI/电商平台/客户 ERP | OpenAPI + EDI 网关 | 订单接入统一经 OMS；状态回传以事件订阅方式提供 |
| 快递100/GPS/温控 | 第三方服务集成 | 归属 TMS 在途服务；设备台账在 MDM |
| 地图/电子围栏 | 第三方服务集成 | 地址坐标与围栏数据归属 MDM 地址主数据 |
| 外部 TMS 租户（协同） | 租户互联接口 | 通过客户"关联租户"实现双向委托运输 |
| AMS 预约（预留） | 范围外 | 本期仅在 OMS 订单保留"是否预约"标志与推送接口位，不建设预约功能 |

## 3. 服务协作架构

### 3.1 架构图

```
┌────────────────────────── 接入层 ──────────────────────────┐
│ 客户门户(网上下单) │ EDI网关 │ OpenAPI │ Excel导入 │ PC Web   │
└────────────────────────────┬───────────────────────────────┘
                             │
┌────────────────────────── 业务层 ──────────────────────────┐
│  MDM 基础资料 ────── 主数据订阅/查询 ──────► OMS / TMS / BMS │
│                                                            │
│  OMS 订单编排 ──推单──► TMS 运输执行                         │
│       │                                                  │ │
│       │ 出/入库指令                                        │ │ 节点事件(提货/到货/签收)
│       ▼                                                  │ ▼
│  【集成层】──► 外部WMS(仓内作业)      BMS 结算(计费/对账/收付)│
│       ▲__________________________________________          │
│            作业状态/作业量/库存快照回传                     │
└────────────────────────────┬───────────────────────────────┘
┌────────────────────────── 平台层 ──────────────────────────┐
│ 租户/域 │ 角色用户权限 │ 消息 │ 系统日志 │ 自定义 │ 系统设置  │
│ 业务单号 │ 导入导出 │ OpenApi网关(ApiKey→Token) │ 对外集成   │
└────────────────────────────────────────────────────────────┘
```

### 3.2 协作原则

1. **数据所有权**：主数据属 MDM，订单属 OMS，运输单据属 TMS，费用单据属 BMS；跨服务只读消费，写操作必须回到属主服务；
2. **接口契约优先**：服务间交互（查询、推单、事件）必须先定义接口契约文档（归入各服务 PRD 的接口章节）；
3. **事件驱动计费**：OMS 订单审核、TMS 运单节点（提货/到货/签收）、外部 WMS 作业完成均为计费触发事件，BMS 订阅消费，凭证生成时机由"凭证创建规则"配置；
4. **幂等与可追溯**：推单与事件消费幂等（重复推送不重复生成单据）；全部跨服务单据保留来源单号链路（外部订单号→销售订单→出库订单→发货订单→运单→凭证→对账单）；
5. **逆向联动**：撤销/反审核/冲抵等逆向操作沿正向链路逐级回滚并刷新下游（如订单冲抵刷新分段、运单、应收应付、回单）；
6. **降级策略**：集成层或外部 WMS 故障不阻断 OMS/TMS 单据创建，未送达指令可重试；BMS 凭证生成失败进入重试队列并告警。

### 3.3 关键协作场景

| 场景 | 发起方 | 消费方 | 机制 |
| --- | --- | --- | --- |
| 主数据变更分发 | MDM | OMS/TMS/BMS/外部WMS | 变更事件 + 分仓同步指令 |
| 销售订单发布（含运输） | OMS | TMS | 推单生成发货订单（前置校验：地址与客户已在 MDM 维护） |
| 出/入库指令下发 | OMS | 外部 WMS | 集成层推单（前置校验：主数据已分仓同步） |
| 作业结果回传 | 外部 WMS | OMS | 集成层状态回传（收货完成/发货确认/库存快照） |
| 计费触发 | OMS/TMS/外部WMS | BMS | 状态事件订阅 |
| 凭证刷新 | TMS | BMS | 货差/冲抵/改单事件触发费用重算 |
| 结算数据出账 | BMS | ERP | 财务接口 |
| 客户协同运输 | TMS | 外部租户 | 关联租户互联接口 |

## 4. 端到端业务流程

### 4.1 销售出库（订单到收款）

```
客户下单(门户/EDI/API/手工/Excel)
 → OMS 销售订单(审核→发布)
 → OMS 出库订单(提交)
     ├─→ 集成层 → 外部WMS 出库作业(拣货-复核-装车) → 回传发货确认
     └─→ TMS 发货订单 → 审核 → 配载/分段 → 运单(批准→…→签收) → POD
 → BMS 应收凭证(按审核/提货/到货规则) → 合并发票 → 应收对账单
     → 批准 → 收款(收款计划分期) → 实收 → 发票/ERP
```

### 4.2 采购入库（采购到付款）

```
OMS 采购订单(审核→发布) → OMS 入库订单(提交)
 → 集成层 → 外部WMS 入库作业(收货-质检-上架) → 回传作业量与库存
 → OMS 全局库存更新
 → BMS 应付凭证(仓储/增值费) → 应付对账单 → 付款 → 实付
```

### 4.3 纯运输（TMS 主导）

```
TMS 订单(必输客户) → 发货订单 → 审核 → 配载(手工/自动/地图/路线)
 → 运单 → 指派承运商/运输方式/设备/司机 → 提货→在途→节点到货→签收 → POD
 → BMS 应收凭证(客户) + 应付凭证(承运商) → 对账 → 收/付款
```

### 4.4 计费结算（BMS 主导）

```
业务事件(订单审核/运单提货/到货/签收/WMS作业完成)
 → 计费引擎匹配费率合同与计费模式(标准/立方/趟次/包月) → 生成应收/应付凭证
 → 凭证审核(可配置客户审核环节) → 合并发票(相同结算客户+域+贸易条款+服务级别)
 → 对账单(收款计划分期:实收日期=创建时间+账期,实收金额=总运费×比例)
 → 收款/付款 → 实收实付 → 发票 → ERP
```

## 5. 系统级非功能需求

| # | 类别 | 要求 |
| --- | --- | --- |
| N01 | 多租户 | 支持多租户与 PUBLIC/用户域隔离 |
| N02 | 性能 | 单租户日单量 10 万级；列表查询 P95<2s；导入 1 万行≤3 分钟 |
| N03 | 一致性 | 跨服务推单与事件消费幂等、可重试、链路单号全程可追溯 |
| N04 | 审计 | 全部业务与主数据操作留痕（操作人/时间/前后值），保留≥2 年 |
| N05 | 可用性 | 核心作业（接单、配载、结算）可用性≥99.9%；集成故障降级不阻断单据创建 |
| N06 | 安全 | OpenAPI Token 认证；敏感字段按角色脱敏；数据权限按租户/域/授权三级控制 |
